# 엔진 비교 — Unity 6 vs Godot 4.7 (실측)

같은 게임을 두 엔진으로 만들어 놓고 고르기 위한 문서. **추정이 아니라 실제로 돌려 본 수치**만 적는다.
Godot 이식본은 `DetectiveGodot/`에 있고 실행된다.

작성 2026-09-26 · Unity 6000.0.81f1 / Godot 4.7.2-stable-mono / .NET SDK 8.0.425

---

## 0. 결론부터

**로직은 엔진에 묶여 있지 않다.** 이것이 실측의 핵심이고, 덕분에 엔진 결정이 "다시 만들기"가 아니라
"껍데기를 고르기"가 된다.

| | 파일 | 줄 | 엔진 이식 |
|---|---:|---:|---|
| 순수 C# 로직 (§18-1) | 48 | **5,995** | **그대로 공유.** 한 줄도 고치지 않았다 |
| Unity 껍데기 | 27 | 3,833 | 다시 써야 함 |
| Unity 에디터 스크립트 | — | 1,119 | Godot에선 대부분 불필요 (씬이 텍스트다) |
| EditMode 테스트 | 27 | 4,585 | 26개 파일 그대로 통과 |

Godot 쪽에서 새로 쓴 것은 **904줄**이다. 그것으로 지도·이동·벽 충돌·엿듣기·소나 화면·HUD·데이터 검사가 돈다.

**추천: Godot.** 단, 결정을 뒤집는 질문 하나가 남아 있다 — [§6](#6-결정을-뒤집는-질문-3d)를 보라.

## 1. 공유된 것 (복사가 아니다)

`DetectiveGodot/SharedLogic.props`가 Unity 프로젝트의 `.cs` 파일을 **직접 가리킨다**.
두 벌로 복사하지 않는다 — 갈라지는 순간 "같은 게임"이 아니게 된다.

공유 목록은 `python tools/sync_godot.py`가 만들고, 판정 기준은 CLAUDE.md와 같다:
`using UnityEngine` / `using UnityEditor`가 없는 파일.

여기에 **자기 강제력**이 있다. 누가 로직 파일에 UnityEngine을 끌어들이면 그 파일은 공유 목록에서
빠지고 **Godot 빌드가 컴파일 오류로 터진다.** §18-1이 문서상의 약속이 아니라 빌드 게이트가 된다.

공유되는 것: 시간(ms 축)·방 배치와 벽 생성·NPC 스케줄·목격 판정·대화 조립·타임라인 복원·
채점·추리 가능성 검증·엿듣기 전부(가청 판정·재생 장치·청취 세션·대본 검증·미청취 보고서·
음성 배정·이동 트랙)·저장 모델.

## 2. 검증 — 양쪽 다 실제로 돌린 것

### 2.1 컴파일

| | Unity 6 | Godot 4.7 |
|---|---|---|
| 방법 | `-batchmode` (라이선스 필요) | `dotnet build` |
| 클린 빌드 | 분 단위 | **1.4초** |
| 결과 | `error CS` 0 · `warning CS` 0 | **0 오류 · 0 경고** |

공유 로직 5,995줄이 Unity 밖에서 **경고 하나 없이** 컴파일된다. 고친 곳은 없다.

### 2.2 테스트

```
dotnet test SharedLogicTests/SharedLogicTests.csproj
→ 통과!  실패: 0, 통과: 255, 전체: 255, 기간: 303 ms
```

`SharedLogicTests/`는 Unity도 Godot도 참조하지 않는다. Unity의 EditMode 테스트 파일과 순수
로직을 그대로 컴파일해 `dotnet test`로 돌린다. **27개 테스트 파일 중 26개가 그대로 통과한다.**

빠진 하나는 `GameDataTests.cs`로, Unity의 `Resources` 로더 자체를 시험하므로 엔진 밖에서는
의미가 없다. 그 9개가 보던 것(실제 JSON으로 참조 무결성·추리 가능성)은 Godot 쪽에서
`SelfCheck`가 **같은 공유 검사기로** 본다:

```
godot --headless --path DetectiveGodot -- --selfcheck
→ exit 0
  [통과] rooms.json 무결성      방 6개 · 문 5개 · 벽 조각 20개
  [통과] 참조 무결성            인물 5명 · 단서 7개 · 대사 파일 4개
  [통과] 추리 가능성 (case_01)
  [통과] 연출 참조 (art.json)
  [통과] 대본 무결성            발화 267개 · 목소리 5개 · 회차 10:00.0
  [통과] 필요한 사실이 어딘가에서는 들린다
  [통과] 한 방에 고정되면 전부는 못 듣는다
  [통과] 한 회차로 전부 모을 수는 없다
  [통과] 이동 트랙
```

게임의 전제("한 회차로는 전부 들을 수 없다")가 Godot 쪽에서도 기계 판정된다. 판정하는 코드는
Unity 판과 같은 파일이다.

### 2.3 실행

Godot 판이 창에서 돈다. 방 6개를 rooms.json에서 만들고, 267발화 회차를 재생하며,
탐정이 선 방에 따라 같은 방은 전문 / 벽 너머는 웅얼거림으로 들린다.

## 3. 이 프로젝트에 한정한 차이

일반적인 엔진 비교가 아니라, **이 저장소가 실제로 부딪힌 것**만 적는다.

### 3.1 에셋이 텍스트인가 — 가장 큰 차이

이 프로젝트의 설계 원칙 §18-2("손으로만 만들 수 있는 에셋을 만들지 않는다")와
§18-3("사건 데이터는 JSON. ScriptableObject는 GUID YAML이라 텍스트로 안전하게 못 쓴다")는
**Unity의 제약에서 나온 규칙**이다. 그래서 씬을 만들려면 먼저 `SceneBuilder.cs`(1,119줄의
에디터 스크립트 중 큰 몫)를 써야 했다.

Godot에서는 `project.godot`·`.tscn`·`.tres`가 전부 **일반 텍스트**다. `Main.tscn`은 13줄이고
손으로 썼다. diff도 읽힌다. **§18-2가 요구하는 우회가 필요하지 않다.**

데이터의 파생물을 씬에 박지 않는다는 원칙 자체는 엔진과 무관하게 유효해서 Godot 판도 방·벽·
토큰을 rooms.json에서 만든다. 다만 그것이 *강제*가 아니라 *선택*이 된다.

### 3.2 프로젝트 락 — 병렬 작업의 천장

CLAUDE.md에 규칙으로 박혀 있다: **에디터가 열려 있으면 batchmode 금지.** Unity는 프로젝트를
배타적으로 잠그므로 컴파일·테스트·씬 생성이 한 번에 하나씩이고, 사람에게 "에디터를 닫아
달라"고 부탁해야 하는 구간이 생긴다. `DEVELOPMENT_PLAN_RELEASE.md`가 병렬 작업 규칙을
따로 적어 둔 이유가 이것이다.

Godot은 잠그지 않는다. **게임 창이 떠 있는 상태에서 헤드리스 자기검사를 돌려 exit 0을 확인했다**
(stderr 비어 있음). 같은 프로젝트에 두 인스턴스가 동시에 붙는다.

### 3.3 라이선스

Unity는 라이선스가 없으면 batchmode가 return code 198로 거부된다. 이 프로젝트는 그 때문에
MSIX 컨테이너에서 `UnityEntitlementLicense.xml`을 꺼내는 우회를 해야 했고, **라이선스 갱신
(2026-10-24)에 다시 깨진다.**

Godot은 MIT다. 로그인도 라이선스 파일도 없다.

### 3.4 순환 속도

| 작업 | Unity 6 | Godot 4.7 |
|---|---|---|
| 컴파일 확인 | batchmode, 분 단위, 락·라이선스 필요 | `dotnet build` 1.4초 |
| 로직 테스트 | EditMode batchmode, 분 단위 | `dotnet test` 2.7초 (실행 303ms) |
| 데이터 검사 | 에디터 메뉴 또는 batchmode | `--headless -- --selfcheck` 수초 |
| 씬 반영 | `RebuildMainScene` batchmode 필수 | 실행 시 생성, 별도 단계 없음 |

## 4. Godot 이식본의 현재 범위 — 솔직하게

**있는 것**: rooms.json에서 만든 지도(바닥·문·벽 충돌) · 탐정 이동 · 청취점 추적 ·
엿듣기 회차 재생(267발화) · 가청 판정(같은 방 전문 / 벽 너머 웅얼거림 / 그 밖 무음) ·
소나 화면(Tab, 파문이 재생 위치에 묶여 정지하면 같이 멈춘다) · HUD(시계·배속·방·들은 수·
놓친 수·대사 버블) · 재생 조작(재생·정지·±5초·처음부터·배속) · 한글 폰트 · 데이터 자기검사.

**없는 것** — Unity 판에는 있고 아직 옮기지 않았다:

* 조사·단서 상호작용(E), 수사 노트(N), 대화 화면, 고발 화면(F), 시작·결과 화면
* 소리 전부 (`AudioDirector`의 BGM·환경음 교차 페이드, `ProceduralAudio`)
* art.json 기반 바닥 질감·인물 초상화 (`ProceduralTextures`)
* NPC 토큰 표시 (tracks.json은 자기검사에서 읽지만 화면에 그리지 않는다)
* 저장·불러오기 연결

즉 **게임의 정체성(듣고 되돌려 듣는 핵심 루프)은 돌아가고, 화면 다섯 개와 소리가 남았다.**
채점·저장·고발 같은 *로직*은 이미 공유되고 테스트를 통과하므로 남은 일은 그 로직에
화면을 붙이는 작업이다. 904줄로 여기까지 왔으니 나머지는 대략 그와 비슷한 규모로 본다.

## 5. 에셋 — 엔진과 별개의 축

지금 들어가 있는 것은 전부 CC0/퍼블릭 도메인이고 출처는 `CREDITS.md`에 있다.
**이 에셋들은 엔진을 바꿔도 그대로 쓸 수 있다** (PNG·OGG·OTF는 양쪽 다 읽는다).

| 종류 | 현재 | 출처 | 엔진 종속성 |
|---|---|---|---|
| 바닥 질감 6장 | 있음 | ambientCG (CC0) | 없음 |
| 인물 초상화 5장 · 단서 그림 7장 | 있음 | Wikimedia Commons (PD) | 없음 |
| BGM 3곡 · 환경음 · 효과음 3종 | 있음 | Musopen 쇼팽 (PD) | 없음 |
| 폰트 | Noto Serif KR | OFL 1.1 | 없음 |
| **한국어 음성** | **없음** | Azure TTS 예정 ($0.09) | 없음 |

옮길 때 손이 가는 유일한 부분은 **임포트 설정**이다. Unity는 `ArtAssetImporter.cs`
(AssetPostprocessor)가 바닥 질감의 Wrap=Repeat·PPU=512를 맞춘다. Godot은 `.import` 텍스트
파일이라 같은 설정을 텍스트로 적으면 된다 — 오히려 쉽다.

음성은 어느 엔진이든 같다. `docs/TTS_OPTIONS.md`의 결론(Azure S0)과
`tools/tts_audition.py`(비교 청취)는 엔진 결정과 무관하게 유효하다.

## 6. 결정을 뒤집는 질문 (3D)

위의 모든 근거는 **2D를 유지한다면** Godot을 가리킨다.

그런데 이 프로젝트에는 이전에 세운 계획이 하나 있다 — **에셋 팩 B로 3D 구현.**
그 계획이 여전히 유효하다면 저울이 기운다:

* **Unity**: 에셋 스토어가 압도적이다. "팩 B를 사서 넣는다"는 접근이 성립하는 이유가 그것이다.
  URP/HDRP, 조명·라이트맵 도구, 애니메이션 파이프라인이 성숙하다.
* **Godot**: 3D가 되긴 하지만 상업 에셋 생태계가 훨씬 얇다. 사 온 FBX/유니티패키지를 그대로
  넣지 못하고 변환·재조립이 필요하다. 3D 조명·베이킹 도구도 Unity만큼 다듬어져 있지 않다.

**그래서 물어볼 것은 하나다: 3D로 갈 것인가?**

* **2D로 간다** → **Godot.** 위의 실측 근거가 전부 Godot 쪽이다. 남은 이식은 화면 다섯 개와 소리.
* **3D로 간다 (에셋 팩 구매)** → **Unity 유지.** 껍데기 3,833줄이 이미 검증돼 있고, 3D 에셋
  생태계라는 이유가 다른 모든 차이를 덮는다. 이 Godot 이식본은 "로직이 엔진 독립적이다"를
  증명한 자산으로 남겨 두면 된다 — 나중에 언제든 다시 꺼낼 수 있다.

어느 쪽이든 **5,995줄은 손대지 않는다.** 그게 이 문서가 말하려는 전부다.

## 7. 다시 만드는 방법

```bash
# 공유 로직 목록 + 데이터·폰트 사본 갱신 (Unity 쪽이 바뀌면 다시 돌린다)
python tools/sync_godot.py            # --check 로 최신 여부만 확인 (CI용)

# 엔진 없이 로직 테스트
dotnet test SharedLogicTests/SharedLogicTests.csproj

# Godot 판 빌드·검사·실행
dotnet build DetectiveGodot/DetectiveGodot.csproj
godot --headless --path DetectiveGodot --import
godot --headless --path DetectiveGodot -- --selfcheck     # exit 0 = 데이터 통과
godot --path DetectiveGodot                              # 플레이
```

조작: `WASD` 이동 · `Tab` 청취 화면 · `Space` 재생/정지 · `←→` 5초 · `R` 처음부터 ·
`[ ]` 배속 · `Esc` 종료

`DetectiveGodot/data/`·`fonts/`는 Unity 프로젝트의 사본이라 git에 넣지 않는다.
원본은 `DetectivePrototype/Assets/Resources/` 하나이고 `sync_godot.py`가 언제든 다시 만든다.
