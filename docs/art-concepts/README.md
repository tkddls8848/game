저장소 구조를 유지할 것). 같은 게임 화면(rooms.json 좌표 · 엿듣기 0:34 시점)을

나중에도 물어볼 수 있어야 한다.

번호는 **원래 순서를 유지한다.** `png/NN-*.png` 파일명이 그 번호이므로 다시 매기면

## 구현된 둘

**10 소나** — 관찰 모드(T)에서 Tab으로 들어간다. 저택이 어둠에 가라앉고 소리만 파문으로
보인다. 파문 위상이 재생 위치(ms)에 묶여 있어 정지하면 파문도 멈춘다. Unity `SonarView`가
그리고, 판정은 순수 로직 `AudibilityModel`이 한다.

**12 인형의 집** — 2.5D 시험본을 다른 엔진으로 한 번 만들어 보고 **엔진을 Unity로 정한 뒤
제거했다**(`docs/ENGINE_COMPARISON.md`). 확인한 것은 남았다: 컷어웨이 없이 벽 높이만 낮춰도
여섯 방이 한 화면에 들어오고, 안개·톤매핑·비네팅이 무게를 만든다. 뒤 둘은 Unity의
`CameraGrade` 후처리로 옮겼다.

## 01 사건 파일이 기준선인 이유

처음 구현이 "가벼워 보인다"는 지적을 받았고, 원인이 넷으로 드러났다. 전부 이 시안을
코드로 옮기면서 어긋난 것이었다:

* 강조색 채도가 높았다 — `#E8B06A`를 대사·눈금·표시에 두루 써서 아케이드처럼 읽혔다
* 글자에 4px 검은 외곽선이 있었다 — 그것만으로 글자가 스티커가 된다
* 환경광이 그림자를 씻어 냈다(0.75) — 그림자 없는 화면은 납작하고, 납작하면 가볍다
* 사람이 밝은 캡슐 + 머리 위 발광 구슬이었다 — 떠 있는 발광 아이콘은 UI고, UI는 가볍다

고친 수치는 `Assets/Scripts/Art/Palette.cs`에 한 곳으로 모았다. 시안의 팔레트를
**눈대중이 아니라 값으로** 옮긴 것이 이 시안을 기준선이라고 부르는 근거다.

## 08 픽셀 아트를 쓰지 않는 이유

시안 자체의 문제가 아니라 **방향의 문제**다. 이 게임은 `docs/POSITIONING.md`에서
"내러티브 미스터리 · 분위기 호러"로 포지셔닝했다. 도트의 문법은 화면을 가볍게 만들고,
가벼움은 이 게임이 팔려는 정서와 반대다. 시안은 기록으로 남긴다.

## 스크린샷 재생성

```
npm i playwright && npx playwright install chromium
node shoot.js
```

폰트는 Google Fonts에서 받아 `fontcache/`에 캐시한다(커밋하지 않는다).
번호는 화면에 렌더된 값을 읽으므로 탈락 목록이 바뀌어도 파일명이 어긋나지 않는다.

> **`png/00-contact-sheet.png`는 낡았다.** 탈락한 5개를 아직 담고 있다.
> 이 파일은 `shoot.js`가 만들지 않으므로(01부터 찍는다) 자동으로 갱신되지 않는다.
> 남은 7장을 몬타주해 다시 만들거나, 지우고 `index.html` 상단의 칩 목록을 쓰면 된다.
